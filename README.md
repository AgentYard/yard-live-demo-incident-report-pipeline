## CI/CD

Pushing to `main` runs `.github/workflows/deploy.yml`, which calls the platform's
reusable `system-ci.yml` workflow to build, smoke-test, and publish this
orchestrator as `agentyard-system-live-demo-incident-report-pipeline:latest`. That's a **separate** image from
`docker build -t yard-live-demo-incident-report-pipeline` above — this is the one AgentYard's own
"Deploy to Kubernetes" will prefer once it exists in the registry, instead
of falling back to the generic orchestrator image.

Requires an `AWS_ROLE_ARN` repository secret trusted for this specific repo.
If you didn't set that up, the workflow will fail at the AssumeRole step —
either ask whoever administers the platform's AWS account to trust this repo,
or point `AWS_ROLE_ARN` at a role in your own AWS account and adjust
`ECR_REGISTRY` accordingly. This step is optional — everything above (build
locally, run, invoke) works with zero AWS access.

## Editing

This code is fully editable. The orchestrator calls agents over HTTP (A2A protocol) — you can modify the orchestration logic without touching the agents.

To re-import into AgentYard Studio:
```bash
curl -X POST http://localhost:8080/api/systems/import \
  -H "Content-Type: application/x-yaml" \
  --data-binary @system.yaml
```
